# 07 Internationalization, Right-to-Left and Accessibility

Depends on: [02-screen-format.md](02-screen-format.md), [03-components.md](03-components.md), [06-operator-ergonomics.md](06-operator-ergonomics.md).

## 1. What gets translated

| Text | Source | Translation mechanism |
|---|---|---|
| HMI chrome (menus, dialogs, quality names, error codes) | shipped with HMI | i18next resource bundles in `apps/hmi/locales/{lang}/*.json`, ICU MessageFormat |
| Screen text (labels, `text` widgets, state labels, menu labels) | screen documents | `i18n` block in the screen document (section 2) |
| Tag `display_name`, `description`, `enum_labels` | tag config | single language in v1 (contract limitation, section 3) |
| Alarm `message` | tag config, rendered by the alarm engine | single language in v1 |
| API problem details | server | HMI translates by `code`, never displays `title`/`detail` unless no translation exists |

v1 ships English and Hebrew HMI chrome (Hebrew to prove RTL from day one). Additional languages are resource files only.

## 2. Screen text translation

Every user-visible string in a screen can be a plain string (default language) and optionally translated in an `i18n` block keyed by widget id and property path. Translations stay inside the screen document so exporting the screen exports its translations.

```yaml
apiVersion: skyranger/v1
kind: Screen
metadata:
  name: meter_overview
  display_name: "Water meter"
spec:
  default_language: en
  widgets:
    - id: flow
      type: value
      bind: { value: ${meter}/flow_rate }
      props: { label: "Flow rate" }
    - id: meter_health
      type: indicator
      bind: { value: ${meter}/health }
      props:
        states:
          - { when: { eq: 2 }, style: normal,   label: "Reporting" }
          - { when: { eq: 1 }, style: warning,  label: "Stale" }
          - { when: { eq: 0 }, style: abnormal, label: "Offline" }
  i18n:
    he:
      metadata.display_name: "מד מים"
      flow.props.label: "ספיקה"
      meter_health.props.states.0.label: "מדווח"
      meter_health.props.states.1.label: "לא עדכני"
      meter_health.props.states.2.label: "לא מקוון"
```

Keys are `{widget_id}.{property path with dot-separated indexes}` or `metadata.display_name`. The validator warns about keys that do not match any string property (stale translations after edits). The designer has a "missing translations" report per language.

Language selection: user preference (08) > browser `navigator.languages` matched against available bundles > gateway default (`hmi.default_language` setting). Switching language does not reload the page.

## 3. Tag display names (contract limitation)

`display_name` in tag-model.md is a single UTF-8 string (max 128). A Hebrew-only plant can simply configure Hebrew display names. A bilingual plant cannot translate them in v1.

**Contract proposal (additive):** optional `display_names: {he: "...", ar: "..."}` map on tag definitions, and the same for alarm `message` (`messages: {...}`), returned as-is by `GET /tags/{id}`. The HMI picks the user's language and falls back to `display_name`. Until accepted, screens can override labels via `props.label` + `i18n`.

## 4. Right-to-left (Hebrew, Arabic)

### 4.1 Mechanism

- `<html dir="rtl" lang="he">` set from the active language's direction (from `Intl.Locale` text info where available, else a static list: `he`, `ar`, `fa`, `ur`; `Intl.Locale.prototype.textInfo` support is UNVERIFIED across browsers, so the static list is the primary source).
- All CSS uses **logical properties**: `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`, `border-inline-start`. A lint rule (stylelint `liberty/use-logical-spec` or equivalent, UNVERIFIED plugin name) rejects physical `left`/`right` in component CSS.
- Radix primitives receive `dir` via their `DirectionProvider` (UNVERIFIED API name).
- Icons with direction (back/forward arrows, "open submenu" chevrons) are mirrored; icons without inherent direction (pump, clock, warning) are not.

### 4.2 What mirrors and what does not

| Element | In RTL |
|---|---|
| Shell layout (menu side, header order, banner Ack button) | mirrored |
| Grid screens | mirrored: `x: 0` is the inline-start (right) column. Screens are authored once and work in both directions |
| Tables and alarm list | columns mirrored (first column at right) |
| **Numbers** | never mirrored; digits are LTR runs. Wrap each formatted value in `<bdi>` (or `unicode-bidi: isolate`) so `-12.5 L/min` does not reorder to `L/min 12.5-` |
| Units next to numbers | number+unit isolated as one LTR run when the unit is a Latin symbol; Hebrew unit names (if translated) follow the text direction |
| Tag paths (`site1/pumphouse/...`) | always LTR in `<bdi dir="ltr">`, monospace |
| **Trend time axis** | **not mirrored**: time flows left to right in both directions (common convention in Hebrew engineering software; confirm with users, see Open questions). Axis labels translated |
| **Canvas P&ID screens** | **not mirrored**: process drawings reflect the physical plant. Text labels inside are RTL text but positioned as drawn |
| Bars and gauges | horizontal bars fill from inline-start by default (`props.fill_from: start` mirrors; `left` fixes it); gauges are not mirrored (clockwise increase) |
| Sliders/steppers in control dialogs | minus at inline-start, plus at inline-end |

`layout.mirror: auto | never` on a `grid` screen lets an integrator pin a screen to LTR geometry if it mimics a physical panel.

### 4.3 Testing RTL

- Designer preview has an LTR/RTL toggle (04).
- Playwright runs the water meter dashboard in `en` and `he` and compares screenshots; a test asserts no element with physical `left`/`right` computed position differences beyond mirrored layout (approximate; mostly visual review in v1).
- Bidi test strings in fixtures: Hebrew labels mixed with Latin units, negative numbers, paths.

## 5. Numbers, dates, times, units

- Numbers: `Intl.NumberFormat(locale)`. Hebrew uses Western digits by default, so no digit-shaping issues; Arabic locales may choose Arabic-Indic digits (`ar-EG` vs `ar-u-nu-latn`); the HMI defaults to Latin digits (`-u-nu-latn`) for all industrial values because operators compare with field instruments, configurable per user.
- Input parsing in control dialogs accepts the locale decimal separator and `.`; ambiguous input (`1,234` in a comma-decimal locale) is rejected with a hint rather than guessed.
- Dates/times: `Intl.DateTimeFormat(locale, { timeZone: gatewayTimezone })`. 24-hour clock by default (plant convention), user-overridable. Relative times ("2 min ago") via `Intl.RelativeTimeFormat`.
- Timezone: always the gateway timezone (`/system/info` `timezone`) for display, shown in the header. A user preference can switch to browser local time for remote viewers, with the zone always labeled.
- Units: UCUM display symbols (03) are language-neutral; optional translated unit names in bundles for screen readers ("liters per minute" / "ליטרים לדקה").

## 6. Accessibility

Target: WCAG 2.2 AA for the HMI chrome, alarm list, trends page, faceplates and dialogs. Dense P&ID canvases cannot fully meet AA (spatial graphics), so every canvas screen must have an equivalent accessible path: each symbol is focusable and announces its state, and the faceplate gives a textual view.

| Requirement | Implementation |
|---|---|
| Keyboard operation | All controls reachable by Tab in `order`; arrow-key navigation within tables and alarm list; `Esc` closes dialogs; global shortcuts (`Alt+A` alarm list, `Alt+H` home) documented and remappable; no keyboard trap |
| Focus visibility | 2 px focus ring with 3:1 contrast in both themes; never removed |
| Names and roles | Each widget has an accessible name: label + value + unit + quality ("Flow rate, 12.0 liters per minute, good"). Symbols: `role="img"` with `aria-label` of state, or `role="button"` when clickable |
| Live updates | Values are **not** `aria-live` (hundreds of changes per second would make a screen reader unusable). Instead: new alarms announced via one polite live region ("High alarm: Meter 01, continuous flow"), throttled to one announcement per 2 s with a summary when bursting; link-down banner is `role="alert"` once |
| Color independence | Shape + text for alarm severity and quality (06) |
| Contrast | 4.5:1 text, 3:1 graphics; token validator (06) |
| Motion | `prefers-reduced-motion` honored (no pipe animation, no blink, static double outline instead) |
| Zoom | Usable at 200% browser zoom on grid screens (reflow); canvas screens scale |
| Target size | 44 px touch, 24 px minimum on desktop (WCAG 2.2 target size minimum is 24x24 CSS px, UNVERIFIED exact wording) |
| Trends | Data table alternative ("Show as table") for the visible range; keyboard cursor; exported CSV |
| Time limits | Idle step-down (05) warns 60 s before and can be extended |
| Errors | Form errors announced and linked with `aria-describedby`; problem `code` translated into plain language |

Tooling: `eslint-plugin-jsx-a11y`, axe-core checks in Playwright on each built-in page and the water meter screen, manual screen-reader pass (NVDA on Windows, VoiceOver on iOS) before each release.

## Decisions made
1. i18next with ICU messages for chrome; screen translations stored inside the screen document in an `i18n` block keyed by widget id and property path.
2. English and Hebrew from v1 to force RTL correctness early.
3. RTL via `dir` on `<html>` and CSS logical properties everywhere; grid screens mirror, canvas P&ID screens and trend time axes do not; numbers, units and paths are bidi-isolated.
4. Latin digits for industrial values by default; gateway timezone for all times, labeled.
5. WCAG 2.2 AA target for chrome, lists, dialogs and faceplates; accessible equivalents for canvas screens; alarm announcements via a throttled polite live region, never per-value live regions.

## Alternatives rejected and why
- **Separate translation files per screen outside the document**: breaks the "one file walks away" property and drifts out of sync.
- **Mirroring trends and P&IDs in RTL**: P&IDs represent physical layouts; time axis convention in the target market appears to be left-to-right (to be confirmed).
- **Physical CSS with an RTL override stylesheet (e.g. rtlcss build step)**: works, but two layouts to maintain; logical properties are well supported in current browsers.
- **FormatJS/react-intl instead of i18next**: also good; i18next has the larger ecosystem and simpler runtime language switching (subjective; either works).
- **`aria-live` on values**: unusable flood for screen-reader users.
