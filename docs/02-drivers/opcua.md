# OPC UA: `opcua` Client Driver and Northbound Server

OPC UA appears twice in Sky Ranger:

1. **Southbound client** (`opcua` driver): reads modern PLCs (S7-1500 built-in server, Beckhoff, B&R, CODESYS), third-party protocol gateways (Kepware, other vendors' gateways) and other SCADA systems.
2. **Northbound server** (`skyranger-opcua-server`): exposes Sky Ranger tags to third-party clients. It supports decision 3 (open standards, no lock-in). It is **not** a driver, and it does not use the driver interface.

All OPC UA spec details below are from memory of OPC UA 1.04/1.05 Parts 4 and 6. Anything marked UNVERIFIED must be checked against the spec (or the OPC Foundation reference stack) before implementation. The contract already marks the quality name mapping and the `nsu=` form as UNVERIFIED.

## Part A: `opcua` client driver

### A1. Library

`github.com/gopcua/opcua` (pure Go, MIT licence, UNVERIFIED: confirm licence file and current maintenance). It is the only serious pure-Go option I know of. Risks to evaluate in a spike before committing (phase 3, implementation-order.md):
- subscription and MonitoredItem stability over days, including reconnect and subscription transfer
- security policies supported (`Basic256Sha256`, `Aes128_Sha256_RsaOaep`, `Aes256_Sha256_RsaPss`; UNVERIFIED which ones the library implements)
- behavior against Siemens S7-1500, CODESYS and the open62541 test server
- whether the library's automatic reconnect can be turned off or observed, so our state machine stays in charge

Fallback if the spike fails: **open62541** (C, MPL-2.0) through cgo. MPL-2.0 is file-level copyleft and acceptable in a sold product if we do not modify its files, or publish modifications to those files (licence check before use, see libraries-and-licensing.md).

### A2. Capabilities and settings

```go
driver.Info{
    Name:          "opcua",
    AddressSyntax: "opcua:{NodeId}   e.g. opcua:ns=2;s=Line1.Flow  opcua:ns=0;i=2258",
    Capabilities:  driver.Capabilities{Browse: true, Discovery: false, Write: true, Push: true, SourceTime: true},
}
```

```yaml
apiVersion: skyranger/v1
kind: Connection
metadata:
  name: s71500-line1
spec:
  driver: opcua
  enabled: true
  timestamp_source: auto
  settings:
    endpoint_url: opc.tcp://192.168.10.30:4840
    security:
      policy: Basic256Sha256          # None | Basic256Sha256 | Aes128_Sha256_RsaOaep | Aes256_Sha256_RsaPss
      mode: SignAndEncrypt            # None | Sign | SignAndEncrypt
      client_certificate: secret://opcua/gw01-client   # cert + key, generated by gateway on first use
      trusted_servers: secret://opcua/trusted          # server cert pins (PEM bundle)
      auto_trust_first: false         # TOFU; schema allows true only with an explicit acknowledgement field
    auth:
      type: username                  # anonymous | username | certificate
      credentials: secret://opcua/line1-user
    session_timeout: 60s
    subscription:
      publishing_interval: auto       # auto = min sampling interval of the items, clamped 100ms..10s
      keep_alive_count: 10
      lifetime_count: 30              # must be >= 3 x keep_alive_count (UNVERIFIED rule)
      max_notifications_per_publish: 1000
      queue_size: 1                   # latest-value-wins at the server too
      discard_oldest: true
    mode: subscribe                   # subscribe | poll
    max_nodes_per_read: 500
    namespace_uris:                   # optional pinning, see A3
      "2": "urn:siemens:s7-1500:line1"
```

Security posture: `policy: None` is allowed but the HMI shows a warning badge on the connection. Certificate handling (generation, storage, rotation, trust list UI) belongs to the security doc. The driver only reads the resolved PEM material from settings.

### A3. Addressing and namespaces

The contract address is `opcua:{node_id}` in string NodeId format: `ns=<idx>;i=<num>`, `ns=<idx>;s=<string>`, `ns=<idx>;g=<guid>`, `ns=<idx>;b=<base64>`. `ns=0` may be omitted (UNVERIFIED that every server accepts that).

Namespace indexes are **not stable** across server restarts or reconfigurations on some servers (`ns=3` can become `ns=4` after a PLC project change). The contract marks `nsu=` as a later option. v1 handles the problem without changing the address grammar:
- At connect, the driver reads the server's `NamespaceArray` (`ns=0;i=2255`, UNVERIFIED NodeId).
- If `settings.namespace_uris` pins an index to a URI and the server now reports that URI at a different index, the driver **rewrites** indexes in memory (ns 2 to ns 4) and logs a warning. If the URI is missing, all items in that namespace get `bad_config_error`.
- If no pin is configured, the driver records the array at first successful connect in its Health/log and warns when it changes.

This gives `nsu=` safety without a contract change. Proper `nsu=` support remains an Open question.

### A4. Subscription model

```text
on connected:
    create one Subscription per distinct publishing interval group
        (items grouped by effective interval like scan classes; publishing_interval = group interval)
    for each item: CreateMonitoredItems(
        NodeId, AttributeId = Value,
        SamplingInterval = Item.Interval (0 -> settings default 1s),
        QueueSize = 1, DiscardOldest = true,
        Filter = DataChangeFilter{Trigger: StatusValue, DeadbandType: None})   # change of value or status
    per-item results -> ItemResult (BadNodeIdUnknown -> not_found, etc.)
on DataChangeNotification: Sample{Value, Quality = map(StatusCode), TSSource = SourceTimestamp}
on StatusChangeNotification (subscription-level bad status): mark items of that subscription bad_comm_failure, recreate subscription
on keep-alive missing > keep_alive_count * publishing_interval * 1.5: link lost -> reconnect
on reconnect: try TransferSubscriptions? No: v1 always recreates subscriptions (simpler, see Decisions)
```

- Trigger `StatusValue` (not `StatusValueTimestamp`) avoids a notification every time the server refreshes only the timestamp.
- **Revised values**: servers may revise the sampling and publishing intervals. Revised values are logged and exposed in Health details. An item revised to more than 4 times the requested interval puts the connection in `degraded` with a message, because the operator asked for something the server will not deliver.
- **Server limits**: if `CreateMonitoredItems` fails with too many items (`BadTooManyMonitoredItems`, UNVERIFIED name), the driver creates more subscriptions up to the server's `MaxMonitoredItemsPerSubscription` (read from `ServerCapabilities` if present), and otherwise falls back to `poll` mode for the remaining items.
- **Initial value**: OPC UA sends the current value as the first notification after creating a MonitoredItem (UNVERIFIED that every server does this). If it has not arrived within 2 publishing intervals, the driver does a one-shot `Read` for those items.

### A5. `stale_after` and OPC UA

A subscription only reports changes. A setpoint that has not changed for a week sends nothing, which is correct and healthy. **`stale_after` must not be set on OPC UA tags in subscribe mode** (it would make healthy steady values `uncertain_last_known`). The link is monitored by subscription keep-alives instead. The driver does not resend unchanged values. The config validator should warn when `stale_after` is set on a tag whose connection has `Capabilities.Push` and is not Sparkplug. That rule belongs to the tag engine/config doc and is raised in Open questions.

### A6. Poll mode

`mode: poll` uses the shared scheduler (scanning.md). The planner groups items per scan class into `Read` requests of up to `max_nodes_per_read`. Poll mode is for servers with broken subscriptions (some embedded servers) and for tags with `stale_after`.

### A7. StatusCode to quality mapping

OPC UA StatusCodes are 32-bit. The top 2 bits are severity: `00` Good, `01` Uncertain, `10` Bad (UNVERIFIED bit layout). The driver maps the severity class first, and refines with specific codes:

| OPC UA StatusCode (symbolic, UNVERIFIED) | Sky Ranger quality |
|---|---|
| `Good` | `good` |
| `GoodLocalOverride` | `good_manual` |
| other Good* | `good` |
| `UncertainLastUsableValue` | `uncertain_last_known` |
| `UncertainEngineeringUnitsExceeded` | `uncertain_eng_range_exceeded` |
| `UncertainInitialValue` | `uncertain_initial_value` |
| other Uncertain* | `uncertain` |
| `BadNotConnected` | `bad_comm_failure` (note: the server's upstream link to *its* device is down; our link is fine, so not `bad_not_connected`) |
| `BadCommunicationError`, `BadTimeout` | `bad_comm_failure` |
| `BadDeviceFailure`, `BadSensorFailure` | `bad_device_failure` |
| `BadNodeIdUnknown`, `BadNodeIdInvalid`, `BadConfigurationError`, `BadAttributeIdInvalid` | `bad_config_error` |
| `BadOutOfService` | `bad_out_of_service` |
| `BadWaitingForInitialData` | `bad_waiting_for_initial_data` |
| `BadTypeMismatch` | `bad_type_mismatch` |
| `BadUserAccessDenied`, `BadNotReadable` | `bad_config_error` |
| other Bad* | `bad` |

Deliberate difference from the contract table: tag-model lists `BadNotConnected` as the "likely equivalent" of `bad_not_connected`. In a protocol gateway (for example Kepware fronting a Modbus device), `BadNotConnected` means the gateway's southbound link is down, while our connection to the gateway is up. tag-model's rule "`bad_not_connected` means we cannot hear the network" points to `bad_comm_failure`. This is flagged in Open questions. Unknown codes fall back by severity class.

Service-level errors (session or channel) map through reliability.md section 4: `BadSecurityChecksFailed`, `BadCertificateUntrusted`, `BadIdentityTokenRejected`, `BadUserAccessDenied` at activation go to `faulted` (`unauthorized`). `BadTooManySessions` is retryable.

### A8. Types

| OPC UA built-in type | Natural |
|---|---|
| Boolean | `bool` |
| SByte, Int16, Int32, Int64 | `int64` |
| Byte, UInt16, UInt32, UInt64 | `uint64` |
| Float, Double | `float64` |
| String, LocalizedText (text only), QualifiedName (name only), Guid, NodeId (as string) | `string` |
| DateTime | `datetime` (OPC UA epoch 1601; library converts, UNVERIFIED) |
| arrays, ExtensionObject (structures), ByteString, XmlElement | `unsupported` in v1 |

Enumeration-typed values arrive as Int32 and map to `int64`. The `enum_labels` can be filled from the server's `EnumStrings` at approval time; that is a discovery-service feature.

### A9. Browse

`Browse(start)` walks `HierarchicalReferences` from `start` (default `ns=0;i=85` Objects folder, UNVERIFIED NodeId) one level per call, paging with `ContinuationPoint` mapped to `PageToken`. `Variable` nodes become `points` with `datatype` from the node's `DataType` attribute and `writable` from `UserAccessLevel` bit CurrentWrite. `Object` nodes become `devices` with `device_key = opcua:{node_id}`. Browse never recurses on its own: deep PLC namespaces can have hundreds of thousands of nodes.

### A10. Writes

`Write` service, `AttributeId = Value`, Variant built from the node's `DataType` (read once and cached at subscribe). Writing a `float64` value to an Int16 node: range-check, then send as Int16. Writing NaN: `type_mismatch`. Result StatusCode is mapped with A7 (Good to ok, `BadUserAccessDenied`/`BadNotWritable` to `not_writable`, others to `device_error`). Timeout means `timeout` (unknown outcome).

## Part B: northbound OPC UA server (`skyranger-opcua-server`)

### B1. Shape

A separate process, supervised by `skyrangerd` like a driver (same restart backoff, same resource limits). It is not a `driver.Driver`. It is a **client of the public API** (REST + WebSocket, api.md) with an API key of role `viewer` (or `operator` if writes are enabled). Using the public API means:
- it uses the same auth, audit and write validation as everything else
- it can run on another box
- it adds no new internal contract

Cost: one WebSocket subscription to all tags. At 20 000 tags with 100 ms batching this is fine.

### B2. Address space

```
Objects/
  SkyRanger/                          (ns=1, namespace URI "urn:skyranger:{gateway_id}")
    site1/                            FolderType per path segment
      pumphouse/
        meter01/
          total_volume                BaseDataVariable, NodeId ns=1;s=site1/pumphouse/meter01/total_volume
          flow_rate                   Properties: EngineeringUnits (UCUM -> UNECE code mapping, UNVERIFIED), EURange from eng_range
    _system/connections/...
```

- NodeId is `ns=1;s={tag path}`. This is human-readable and stable as long as the path is stable. A rename changes the NodeId. A second, stable alias `ns=1;g={tag_id}` (GUID NodeId) is exposed through a reference so robust clients can pin it. UNVERIFIED whether many clients handle GUID NodeIds well.
- Value: Variant of the matching built-in type (`uint64` to UInt64, and so on). SourceTimestamp = `ts`. ServerTimestamp = `ts_gateway`. StatusCode = reverse of the A7 table (one representative OPC UA code per Sky Ranger quality).
- History: HistoryRead is **not** in v1. Clients that need history use SQL or REST. Alarms and Conditions are **not** in v1 (large spec surface).
- Writes: disabled by default. When enabled, an OPC UA Write turns into `POST /api/v1/tags/{tag_id}/write?wait=10s`, and the API result maps back to a StatusCode.
- Security: `None` disabled by default. `Basic256Sha256` SignAndEncrypt with username auth mapped to Sky Ranger users (security doc).

### B3. Library

Server-side maturity of `gopcua/opcua` is lower than its client side (UNVERIFIED: it gained a server package in recent versions, and its completeness is unknown). Options, to be decided after the client spike:

| Option | Licence | Risk |
|---|---|---|
| `gopcua/opcua` server package | MIT (UNVERIFIED) | maturity unknown |
| open62541 via cgo or as a small C program speaking our API | MPL-2.0 | cgo build complexity, but open62541 is a widely used, certified-profile server (UNVERIFIED certification status) |
| Commercial SDK (Unified Automation, Softing, Prosys) | commercial | cost per unit, proprietary in an open product |

The northbound server is phase 6 and not needed for milestone 1 or the first customer projects.

## Decisions made
1. Client library: `gopcua/opcua`, after a time-boxed spike. Fallback: open62541 via cgo.
2. Subscribe mode by default, `QueueSize 1`, trigger StatusValue, one subscription per interval group. Subscriptions are always recreated after reconnect (no TransferSubscriptions in v1).
3. Namespace index drift is handled by optional `namespace_uris` pinning in settings, without changing the contract address grammar.
4. `BadNotConnected` from a server maps to `bad_comm_failure`, not `bad_not_connected`, because our link is up.
5. Browse is one level per call, never a recursive walk.
6. The northbound OPC UA server is a separate process that is a client of the public REST/WS API. No HistoryRead or A&C in v1. Writes are off by default.

## Alternatives rejected and why
- **TransferSubscriptions on reconnect**: saves a few round trips. It is error-prone and server support varies. Recreating is simple and correct.
- **QueueSize > 1**: we do not have a non-coalescing path (store-and-forward is deferred), so queued values would be coalesced anyway.
- **Northbound server inside `skyrangerd`**: a crash in an OPC UA stack (cgo in particular) would take down the core.
- **Northbound server on the internal MQTT bus**: no write path, and QoS 0 retained values can be missed.
- **Commercial OPC UA SDK now**: cost and lock-in before there is revenue.

## Open questions
- The contract's "likely OPC UA equivalent" column lists `BadNotConnected` for `bad_not_connected`. This doc maps it to `bad_comm_failure`. The contract table should be clarified.
- Add `nsu=` to the contract address grammar (`opcua:nsu=urn:...;s=Line1.Flow`)? It would make `namespace_uris` pinning unnecessary.
- Config validation warning for `stale_after` on subscribe-mode OPC UA tags belongs in the tag engine/config doc.
- UCUM to OPC UA `EUInformation` (UNECE codes) mapping table is UNVERIFIED and needs its own small task.
- Is TOFU (`auto_trust_first`) acceptable for commissioning, given the security posture? Security doc decides.
- All OPC UA symbolic StatusCode names, NodeIds and bit layouts in this doc are UNVERIFIED.
